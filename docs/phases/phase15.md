# phase15 走查修复

> 二期上线后由用户按"注册 → 加购/勾选 → 地址 → 下单 → 支付 → 退款 → 评论 → 看板"手动走查一轮，
> 本阶段只修走查出来的体验缺陷：不加功能、不动硬约束。

## 走查发现与处理

| # | 现象 | 原因 | 改法 |
|---|---|---|---|
| 1 | 注册时提示"密码太常见了"，但没说要什么才行 | 规则只写在输入框 placeholder 里，一打字就看不见 | 密码框下加常驻规则行（至少 8 位 / 不能纯数字 / 不能与用户名太相似 / 别用常见词） |
| 2 | 从顶部导航点分类，列表页里还有一排一模一样的分类 | 分类入口做了两处：全局导航 + `ProductsView` 的分类胶囊 | 删掉胶囊；导航第一项补「首页」，并给当前项加选中态（颜色 + 下划线） |
| 3 | 订单抽屉里「评价商品 / 申请退款」两个按钮错位、右侧溢出 | `.detail-submit` 是 `width:100%`，Element 又给相邻按钮加 `margin-left`，两个 100% 内联元素换行后右移 | 按钮包进 `.detail-actions`，`flex` + `gap` + `margin-left:0`，两个等宽并排、单个占满整行 |
| 4 | 订单明细"商品"列只有"千兆""茶轴"这种规格名 | 下单快照取的是 `SKU.title`（规格），没带商品名 | 快照写成「商品名 规格」；商品名复用 `_ensure_on_shelf` 已经查出来的那批，不加查询 |
| 5 | 后台入口没交代，且没有可用管理员账号 | `--staff` 只设 `is_staff`，没给模型权限；admin 的可见性由权限决定，登录进去是空白页 | 改为同时给 `is_superuser`；订单/券的只读仍由 `ModelAdmin` 覆写保证（超管同样改不了），用例就是拿超管跑的 |
| 6 | 隧道进去了，但点「登录」直接 403（CSRF 验证失败） | nginx 传 `Host $host`，把端口丢了；浏览器 Origin 是 `http://127.0.0.1:8081`，Django 拿它跟 `http://127.0.0.1` 比，判不一致 | 三处 `proxy_set_header` 改成 `$http_host`；顺带修好分页响应里缺端口的绝对链接 |

第 4 条只影响**新订单**：历史订单是快照，按快照语义不该回改，所以库里会同时存在
"头戴式游戏耳麦 黑色"（新）与"千兆"（旧）两种标题，这是有意的。

## 踩到的坑

- **`--staff` 不等于能进后台**：只有 `is_staff` 时 admin 首页是空白，因为可见性按模型权限算。
  当时以为"加个 flag 就行"，直到准备走查后台才发现。
- **Element Plus 的相邻按钮 `margin-left`**：`width:100%` 的按钮并排时，这条外边距会把第二个顶出去，
  症状是"右边多出来一截"而不是"没对齐"，容易误判成宽度问题。
- **快照拼标题要截断**：`OrderItem.title` 是 120 字符，商品名 + 规格拼起来可能超，拼完统一 `[:120]`。
